# Agent 工作方式与交互渠道

> 说明：本系统的 agent 以**「个人本地 Bot」为主**：一个后台常驻 agent 跑在**员工本机**，用户**在飞书里**和它交互。核心是同一个 pi agent + pi-coworker 扩展（知识/权限/安全/审计），通过 lark-cli 与飞书能力捆绑。

## 1. 核心模型：个人本地 Bot Agent

```
员工本机
┌──────────────────────────────────────────────┐
│ Bot Agent 守护程序（常驻，agent/ 目录）          │
│  ├─ lark-cli event consume（个人 Bot 应用）     │ ← 收消息/卡片回调
│  ├─ pi --mode rpc（coworker 工具 + 可选本地工具） │ ← 工作目录 = 本机
│  ├─ 身份：用户自己的 lark-cli（个人数据）         │
│  ├─ 模型：用户自己的 provider（非公司网关）       │
│  └─ 安全：限流/审计/白名单/写确认                │
└──────────────────────────────────────────────┘
        ↑ 私聊/群@（自然语言/点卡片）
        用户（飞书 App）
        ↓ 回复（文本 / 交互卡片 / 更新卡片）
```

- **交互全在飞书**：零安装，员工在飞书里直接和"自己的 Bot"对话。
- **agent 在本地**：数据不出本机、用用户自己的身份与模型、还能做本地文件/命令操作（可选开启）。
- **通过 lark-cli 绑飞书能力**：Bot 应用收消息、user 身份读个人数据、卡片处理审批/直授。

### 关键前置

1. 每个员工一个**个人 Bot 应用**：`coworker_bot_setup`（或 `/coworker:bot`）引导——`lark-cli config init --new` 创建应用 → 控制台启用 `im.message.receive_v1`/`card.action.trigger` 两个事件 + 添加「机器人」能力 + 发布版本。
2. 本机**开机 + 守护进程运行**（`cd agent && RUN_MODE=local node src/index.ts`；电脑关机 Bot 离线）。
3. 个人 Bot 设置**仅本人可用**（防止他人 @你的 Bot 触达你的本地权限）。

## 2. 与用户的交互方式

| 你说（飞书里） | 机器人回 |
|---|---|
| "报销流程是什么？" | 文本回答 + 来源链接（agent 用 knowledge 工具） |
| "申请研发知识库" | 🔐 权限卡片：[一键申请] [查看可申请权限] |
| "查看我的权限" | 📋 权限目录卡片（每项带申请按钮） |
| "入职指引" | 🎒 入职三步曲卡片：[我完成了] [联系 IT] |
| "检查我的环境/登录" | agent 用 check_env/auth_status 处理（split-flow 扫码登录） |
| 点卡片按钮 | 回调处理 → 卡片原地更新（如"✅ 已开通"） |

**登录（split-flow）**：agent 发起授权 → 展示**链接 + 二维码** → 结束本轮等你授权 → 回复"已授权" → agent 完成登录。

## 3. 补充模式

| 模式 | 位置 | 身份 | 用途 |
|---|---|---|---|
| **个人本地 Bot**（默认） | 本机 | 用户 | 个人全功能（问答/权限/入职/本地） |
| **公司共享知识机器人** | 服务器 | bot | 全员群 @ 的百科/制度机器人（7×24、只读） |
| **CLI**（可选） | 本机 | 用户 | 开发者用 `pi` + `/coworker:*`（最全） |
| **桌面 GUI**（可选） | 本机 | 用户 | 仅作为守护进程的托盘/启动器；交互本身在飞书 |

> **桌面 GUI 已降级为非必选项**：飞书内交互已满足日常；GUI 只保留"控制守护进程"的轻量入口。

## 4. 安全边界

- 白名单：只能申请 catalog 登记权限、检索 knowledge 登记源。
- 写操作：卡片按钮确认 / 对话内确认；高风险 lark-cli 门禁不自动 `--yes`。
- 身份一致：不静默切换 `--as`；个人本地 Bot 用用户身份，共享机器人用 bot 身份。
- local 模式默认禁本地工具（`LOCAL_ENABLE_SHELL=1` 显式开启）。
